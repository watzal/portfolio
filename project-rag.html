01

Overview

MediBot is a healthcare chatbot built on Retrieval-Augmented Generation , a technique that combines the reasoning power of large language models with precise retrieval from a curated knowledge base. Rather than relying on an LLM's training data alone, MediBot retrieves relevant passages from medical literature before generating an answer, making responses grounded and verifiable.

The result is a chatbot that can answer clinical questions, explain drug interactions, and summarise medical concepts with far greater accuracy than a vanilla LLM — and crucially, with traceable sources behind every answer.

02

The Problem

General-purpose LLMs hallucinate in medical contexts. They confidently produce plausible-sounding but factually wrong answers about drug dosages, symptoms, and treatment protocols — which in a healthcare setting is dangerous. The problem isn't intelligence, it's grounding.

RAG solves this by separating retrieval from generation: the model never makes up facts it wasn't given. Every answer is anchored to actual medical text, and the source passage is retrievable. This makes the system auditable — essential for any healthcare application.

03

Key Features

📑

Medical Literature Ingestion

Ingests and chunks medical documents, embedding each chunk into a high-dimensional vector space.

🔍

Semantic Vector Search

Uses Pinecone to retrieve the most semantically relevant passages for any query in milliseconds.

🧠

Context-Aware Generation

LangChain injects retrieved context into the prompt so the LLM answers from facts, not memory.

📋

Source Traceability

Every answer references the source passage it was generated from — fully auditable responses.

💬

Conversational Interface

Multi-turn conversation support with memory so follow-up questions stay in context.

⚡

Low Hallucination Rate

By grounding answers in retrieved text, the system dramatically reduces LLM hallucinations on clinical topics.

04

Technical Architecture

Classic RAG pipeline: documents are chunked, embedded, and stored in Pinecone at index time.
At query time, the user's question is embedded and used to retrieve the top-k most similar chunks, which are then injected as context into the LLM prompt via LangChain.

Challenges & Learnings

Too large and the retrieved context overwhelms the prompt window. Too small and you lose the surrounding context that gives meaning to a sentence. Finding the right chunk size and overlap for medical text (which is dense and technical) required significant experimentation.
Embedding quality directly determines retrieval quality. Medical terminology is highly specialised, general-purpose embeddings sometimes miss semantic similarity between clinical synonyms. Testing multiple embedding models was a key part of the pipeline.
Building this project gave me a deep understanding of the full RAG stack: from document ingestion and vector indexing to retrieval tuning and response generation. It became the foundation for my thinking on all subsequent LLM projects.
